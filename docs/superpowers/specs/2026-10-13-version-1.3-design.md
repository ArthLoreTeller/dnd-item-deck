# The Reliquary Version 1.3 Design

## Intent

Version 1.3 turns the existing deck and character sheet into a compact player companion. Players can manage inventory, review skills, learn SRD spells, take session notes, and buy ordinary equipment without leaving the app. The release preserves the existing offline-first browser storage model and keeps Carried Load and Currency UI behavior intact.

## Scope and constraints

- Use the official 2024 rules content from SRD 5.2.1.
- Store SRD content locally so the app works offline.
- Include the SRD 5.2.1 CC BY 4.0 attribution specified by Wizards of the Coast.
- Keep one persisted character profile and one Zustand store.
- Preserve existing saves and support importing backup versions 1 and 2.
- Do not change the Carried Load formulas, exclusions, status copy, or visible component.
- Do not change the visible Currency UI. Shop transactions may call new currency-domain helpers behind it.
- Keep the requested Parchment theme label as Parchment.
- Leave replacement sound file paths in a centralized waiting state until the user supplies assets.

## Navigation and routes

The hash router supports these pages:

- `#/deck`
- `#/inventory`
- `#/character`
- `#/skills`
- `#/spells`
- `#/spell-tome`
- `#/notes`
- `#/shop`
- `#/settings`

The existing circular navigation becomes a collapsible Corner Menu. The collapsed control remains reachable on every page. The expanded menu uses icon-only buttons with accessible names and concise tooltips. It contains Deck, Inventory, Character, Skills, Spells, Notes, Shop, and Settings.

Roll D20 remains a contextual action. Read Details remains available but moves out of the Corner Menu. A small book or information icon beside the displayed deck card opens the existing item journal. Inventory rows expose a compact inspect icon for the same action.

The sound control moves from navigation to Settings.

## Themes

User-facing labels change as follows:

- Love becomes Blossom.
- Woody becomes Mahogany.
- Optic becomes Noir.
- Parchment remains Parchment.

Persisted theme keys remain compatible. Existing `love`, `woody`, and `optic` values map to the renamed labels without resetting user preferences. Mahogany receives a new deep wood background and primary palette. Every control, including inventory sort text and select options, must meet readable contrast in each theme.

## Sound settings

A single SFX manifest maps every sound event to an asset path. Each entry starts with a clearly labeled waiting placeholder. Playback treats a waiting or missing path as silence and never interrupts the user action that requested the sound.

Settings contains:

- Sound enabled or disabled.
- Master SFX volume.
- Reduced-motion preference.
- Theme selection.

The persisted sound settings migrate from the current `muted` boolean. The volume defaults to full volume for existing users unless sound was muted.

## Inventory

The Inventory page returns to a dense row layout. Each row contains compact artwork or category icon, item name, rarity, quantity badge, carried state, weight, and small actions. The scrolling list keeps scroll behavior while hiding the visible scrollbar with `scrollbar-width: none` and a hidden WebKit scrollbar.

Hover, keyboard focus, and tap use the same restrained row highlight and tooltip treatment. The effect must not move nearby content or replace readable text with icon-only information.

### Stacking

Only Common and Uncommon items may stack. Two items match when their names are equal after trimming whitespace and comparing case-insensitively, and their normalized rarities match.

Ordinary equipment stores quantity directly. Matching shop purchases increase that quantity.

Relic cards keep separate records so IDs, progression, attunement, artwork, and backup history remain intact. The Inventory page may render matching eligible records as one stack. It must split the display when a record gains unique state, including a different name, rarity, attunement state, progression state, or other card-specific edit that changes its effective identity.

### Consumables

Equipment and custom item records support an explicit `consumable` flag. The SRD catalog assigns this flag to suitable entries. Custom item editing exposes a Consumable checkbox.

Consumable rows show `[Consume]`. Consuming subtracts one unit. Quantity one removes the item. The action stores enough state for the existing notification pattern to offer one-step Undo. Missing or empty items leave state unchanged and show a concise status.

## Character page

The Character page removes the top Overview/Saves/Skills navigation, Check Roll Mode, Checks & Saving Throws, and Rest & Hit Dice sections. Stored legacy values remain valid so old saves and backups do not fail validation.

The page reduces padding and vertical gaps. Identity and portrait render first, followed directly by this stat block:

| HP / Max HP | Temp HP | Hit Die |
| --- | --- | --- |
| Proficiency Bonus | Speed ft | Initiative | AC |

The implementation uses a three-column first row and four-column second row, with responsive stacking at narrow widths. Initiative uses its override when present and otherwise uses the Dexterity modifier. Proficiency Bonus uses its override when present and otherwise derives from total class level. Hit Die shows the first configured hit-die pool, including its remaining and maximum count; it shows an em dash when no pool exists.

Ability scores, class levels, attacks, resources, and conditions remain editable in compact sections. Currency and Carried Load retain their existing visible UI and calculations.

## Skills page

Skills lists all 18 SRD skills as compact rows, for example `Acrobatics (Dex) +0`. Rows have no roll buttons and no large cards.

Each row retains compact proficiency and override editing. The displayed bonus uses the existing ability, proficiency bonus, proficiency level, and override rules. Hover, focus, and tap expose a brief description derived from SRD 5.2.1. Descriptions are stored locally with the skill definitions.

## Spells page

The Spells page header displays Modifier, Spell Attack, and Save DC in one row. Values use the selected spellcasting ability and existing proficiency logic.

A centered Spell Tome icon links to `#/spell-tome`.

Learned spells group under Cantrip and Levels 1 through 9. Each group sorts spells alphabetically. Existing hand-entered spell entries migrate by normalized name to SRD spell IDs. Entries without an SRD match remain custom learned spells and retain their notes.

## Spell Tome

The Spell Tome contains every spell included in SRD 5.2.1. A local, versioned data module stores spell IDs, names, levels, and the rules fields needed for display.

The page provides:

- A case-insensitive name filter.
- A level filter for All, Cantrip, and Levels 1 through 9.
- Compact rows such as `Chill Touch (Cantrip) [Learn]`.
- Expandable or popover details containing the SRD rules text.

Learning adds a spell once to the current profile. A learned spell row displays a disabled Learned state. The Spells page reflects the change immediately.

## Notes page

Notes combines content previously split across the Character page:

- Features.
- Proficiencies and languages.
- Character and session notes.

The page uses compact editable text areas and persists through the existing profile fields. Migration preserves `sheet.features`, `sheet.languages`, and `profile.notes` without rewriting their content.

## Shop

The Shop presents the mundane equipment catalog included in SRD 5.2.1. It excludes relics and non-SRD branded content. Search and category controls filter the local catalog.

Each catalog entry includes a stable ID, name, category, price in copper-piece units, weight when supplied by the SRD, rarity, and consumable state. Shop goods use Common or Uncommon rarity only where the source data and app taxonomy support it.

Purchasing performs one atomic store update:

1. Convert the wallet to copper-piece units using standard 2024 coin values.
2. Reject the purchase without mutation when funds are insufficient.
3. Subtract the price.
4. Normalize remaining value back into PP, GP, EP, SP, and CP.
5. Increase a matching equipment stack or add a new equipment record.

The purchase feeds the existing Carried Load system through ordinary equipment data. It does not change load formulas or include coins in carried weight.

## Persistence and backups

The Zustand persistence version increments from 3 to 4. Migration adds defaults for learned spell IDs, consumable metadata, SFX volume, and reduced-motion preference while preserving existing profile, equipment, inventory, notes, currency, and relic state.

Backup export advances from version 2 to version 3 and includes the new profile and equipment fields. Import accepts versions 1, 2, and 3. Old backups receive safe defaults. Version 3 backups validate catalog references, learned spell IDs, consumable values, quantities, and currency before changing state.

## Data boundaries

The implementation keeps focused modules:

- SRD skill definitions and descriptions.
- SRD spell records and lookup helpers.
- SRD mundane equipment catalog.
- Coin conversion and purchase helpers.
- Inventory grouping and consumable operations.
- Theme compatibility and labels.
- SFX manifest and playback settings.

Pages read those modules through small selectors and actions. Components do not duplicate spell matching, stack-key normalization, or coin arithmetic.

## Error handling and accessibility

- Duplicate spell learning is idempotent.
- Missing SFX assets fail silently.
- Invalid catalog data fails validation during development.
- Shop failures and consumption failures leave persisted state unchanged.
- Tooltips work through hover, keyboard focus, and tap.
- Icon-only controls include accessible names.
- Compact layouts retain touch targets near 44 pixels on coarse pointers.
- Search, filter, Learn, Consume, purchase, and navigation controls remain keyboard operable.

## Verification

Automated tests cover:

- New and legacy routes.
- Theme labels, Mahogany contrast tokens, and saved-key migration.
- Profile/store/backup migration.
- Skill ordering, bonus display, and description availability.
- Spell search, level filtering, grouping, sorting, learning, duplicate prevention, and legacy spell migration.
- Common/Uncommon stack grouping and split conditions.
- Consumable decrement, removal, invalid calls, and Undo.
- Coin conversion, normalization, insufficient funds, and atomic purchases.
- Shop purchases merging into matching equipment.
- Missing/waiting SFX paths and persisted volume.
- Preservation of Carried Load and Currency UI behavior.

Final verification runs the complete test suite, linter, production build, and browser checks at desktop and mobile widths. Browser checks cover Corner Menu interaction, card-adjacent Read Details, tooltip access, scrollbar hiding without lost scroll behavior, responsive stat layout, learning a spell, consuming an item, and buying an item.
