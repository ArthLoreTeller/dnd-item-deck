# The Reliquary Version 1.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the compact version 1.3 player companion with revised themes and navigation, inventory stacking and consumption, SRD 5.2.1 skills/spells/shop data, focused character pages, and configurable waiting-state SFX.

**Architecture:** Keep the existing React/Vite application and single persisted Zustand store. Add focused domain modules for SRD data, inventory grouping, coin arithmetic, and audio assets; pages consume those interfaces without duplicating rules. Upgrade local persistence to version 4 and backups to version 3 while accepting earlier data.

**Tech Stack:** React 19, Zustand 5, Vite 8, Lucide React, CSS, Node.js built-in test runner, Oxlint.

**Spec:** `docs/superpowers/specs/2026-10-13-version-1.3-design.md`

## Global Constraints

- Use official SRD 5.2.1 content under CC BY 4.0 and include the exact attribution from the spec.
- Keep SRD data local and add no runtime API dependency.
- Keep one persisted character profile and one Zustand store; persisted store version becomes 4.
- Backup export becomes version 3; imports continue to accept versions 1 and 2.
- Preserve existing profile, equipment, inventory, notes, currency, relic progression, and attunement data.
- Do not change Carried Load formulas, exclusions, status copy, or visible component.
- Do not change the visible Currency UI.
- Use Blossom, Mahogany, Parchment, and Noir labels while preserving legacy theme keys.
- Keep replacement SFX paths in a centralized waiting state until the user supplies assets.
- Follow test-first red/green/refactor cycles and commit each task independently.

## Review Focus

- Two Common/Uncommon relics with the same display key but different attunement or progression must split into separate groups; Task 4 tests this.
- Automatic payment must preserve total value for wallets with mixed denominations and reject purchases one copper short without mutation; Task 6 tests this.
- Legacy spell names with punctuation or capitalization differences must map once, while unmatched entries survive as custom spells; Task 3 tests this.
- A missing audio asset must not reject, throw, or block the triggering UI action; Task 2 tests this.
- Old version 1 and 2 backups with no new fields must import with safe defaults and preserve currency/load inputs; Task 3 tests this.
